The clients (e.g., Web browsers, robots, players, etc.) interact with resource representations via verbs "access": GET, "modify": POST, "erase": DELETE,...
GET POST	GET DELETE







The verbs (actions) are stipulated by a protocol





 remark:
although usually HTTP is used, in some cases other protocols can be used also

example: Realtime API OpenAI adopts WebRTC or WebSocket
developers.openai.com/api/docs/guides/realtime






GET

obtains (gets) a resource representation
does not lead to the server's state modiaication - safe idempotent - identical requests will return
the same response (same representation)

an HTTP method is idempotent if the intended effect on the server of making a single request is the same as the effect of making several identical requests - developer.mozilla.org/docs/Glossary/Idempotent






HEAD

similar to GET, but provides meta-data only (does not offer the actual representation)

e.g., last update, content length,...






PUT

replaces (updates) a resource representation
or eventually creates a resource on the Web server (whose URI is already known)

usually, returns the resource's URI

it is not considered safe, but it is idempotent






PATCH

permits a partial update of a resource representation (PUT does not provide this feature)

it is not safe, nor idempotent






POST

creates a resource (usually, subordinated to another one) optionally, additional processing can be performed
it is not safe, nor idempotent
the client does not know in advance the URI of the resource to be created






DELETE

erases (removes) a resource identified by a URI it is idempotent






OPTIONS

allows the client to determine various requirements regarding a resource (e.g., if a resource could be deleted) or the features exposed by a server
(for example, the support provided by a proxy)

rest: implementation - example #1

Invoking a Web service for URL shortening
https://is.gd/

a new short URL will be created by using
https://is.gd/create.php?format=xml&url=WebAddress


The HTTP request that invokes the Web service:

GET /create.php?format=xml&url=profs.info.uaic.ro/sabin.buraga HTTP/1.1 Host: is.gd

The obtained response, sent by the Web server:



HTTP/1.1 200 OK
Server: nginx
Date: Mon, 11 May 2026 13:32:07 GMT+2
Content-Type: text/xml;charset=UTF-8

<?xml version="1.0" encoding="UTF-8"
<output>
<shorturl>https://is.gd/5sTHVh </shorturl>
</output>




POX (Plain Old XML) representation

// initializing cURL
$c = curl_init ();
// setting the URL of the invoked Web service curl_setopt ($c, CURLOPT_URL,
'https://is.gd/create.php?format=xml&url=profs.info.uaic.ro/sabin.buraga');
// the result of the request will be available as a string curl_setopt ($c, CURLOPT_RETURNTRANSFER, true);
// do not verify the digital certificate used for HTTPS data transfers curl_setopt ($c, CURLOPT_SSL_VERIFYPEER, false);
// getting the representation provided by server (here, an XML document)
$res = curl_exec ($c); // by default, the GET method is used
// closing cURL connection curl_close ($c);

// processing the result with DOM
$doc = new DOMDocument ();
$doc->loadXML ($res);
// getting the content of <shorturl> element
$urls = $doc->getElementsByTagName ('shorturl'); foreach ($urls as $url) {
echo '<p>New short URL is ' . $url->nodeValue . '</p>';
}









Obtaining a picture of cats corresponding to a given HTTP status code

as in the previous example, the Web service is freely available, without authentication, but does not follow all REST principles (no URLs to other resources) - i.e. it is not RESTful

https://http.cat/

define ('URL', 'https://http.cat/301');
$c = curl_init (URL); // initializing LibcURL, indicating service's URL

$opt = [ // array of options for the HTTP request
// data will be available as strings
CURLOPT_RETURNTRANSFER=> true,// do not check the digital certificate CURLOPT_SSL_VERIFYPEER
=> false,// connection timeout (in seconds) CURLOPT_CONNECTTIMEOUT
=> 10,// response timeout (in seconds) CURLOPT_TIMEOUT
=> 10,// 4XX codes will lead to errorCURLOPT_FAILONERROR=> true,// redirects are not accepted CURLOPT_FOLLOWLOCATION
=> false ];curl_setopt_array ($c, $opt);
$res = curl_exec ($c);

// HTTP status code returned by the Web service's server
$codHTTP = curl_getinfo ($c, CURLINFO_RESPONSE_CODE);
// content type offered by the server
$tip = curl_getinfo ($c, CURLINFO_CONTENT_TYPE);
// did we successfully receive an image in JPEG format? if ($codHTTP == 200 && $tip == 'image/jpeg') {
header ('Content-Type: ' . $tip); // send the proper MIME type
echo $res; // display the representation of the obtained resource (here, the JPEG image)
} else {
// send the status code returned by the service http_response_code ($codHTTP);
header ('Content-Type: text/plain'); echo 'Status code: ' . $codHTTP;

}
curl_close ($c);	// close the connection with the Web server
